## Aufgabe 01 - Eigenschaften einer Grammatik

> Besitzen die folgenden Grammatiken die LL(1)-Eigenschaft?
> 
> Begründen Sie Ihre Antwort in textueller Form (warum LL(1), warum nicht LL(1)). Sollte es mindestens eine LL(1)-Verletzungen geben, geben Sie bitte **alle** an. Geben Sie zudem für jede Grammatik, welche die LL(1)-Eigenschaft nicht besitzt, die theoretisch minimale Anzahl an Vorgriffssymbolen an, die für das Parsen der jeweiligen Grammatik notwendig wäre

> a.)
> 
> ```
> Temperature = ["-"] ( Celsius | Kelvin ) .
> Celsius = { number } "◦C" .
> Kelvin = { number } "K" .
> ```
> 
> *Beispielsätze*: `5°C, -12K, 273°C, 1000K`

Nicht LL(1)-konform, da das First-Set von Celsius und Kelvin beides `number` enhält und die Mengen somit nicht disjunkt sein können. Man bräuchte mindestens 2 Lookaheads damit ein richtiges Parsing ermöglicht wird.

> b.)
> 
> ```
> Locals = "class" ident "{" { VarDecl | FuncDecl } "}" .
> VarDecl = "int" ident { "," ident } ";" .
> FuncDecl = "fn" "int" ident "(" ")" ";" .
> ```
> 
> *Beispielsatz*: `class C { int a, b, c; fn int mul(); fn int add(); }`

LL(1) konform, da First(VarDecl) = `"int"` und First(FuncDecl) = `"fn"` sind. Somit sind beide Mengen disjunkt.

> c.)
> 
> ```
> Var = ident ":" Type .
> Type = ( Primitive | FuncType ) .
> Primitive = "i32" | "f64" .
> FuncType = Type "->" Primitive .
> ```
> 
> *Beispielsatz*: `i: i32, pi: f64, id: i32 -> i32, add: i32 -> i32 -> i32`

Nicht LL(1)-konform, weil First(Type) = First(Primitive) $\cup$ First(FuncType). First(Primitive) = {"i32", "f64"}. First(FuncType) = First(Primitive). Man bräuchte 2 Lookaheads um korrektes Parsing zu bekommen.

## Aufgabe 02 - Beseitigung von LL(1)-Konflikten mittels Faktorisierung

> Beseitigen Sie in folgenden Grammatiken die enthaltenen LL(1)-Konflikte mittels Einsetzen und Faktorisierung. Geben Sie dazu eine umgeformte, ggf. vereinfachte EBNF Grammatik an.

> a.)
> 
> ```
> StructDecl = ident "=" "{" { Value | NullableValue } "}" .
> Value = ident ":" Type .
> NullableValue = ident ":" "?" Type .
> Type = "i32" | "i64" | "string" .
> ```
> 
> *Beispielsätze*: 
> 
> - `student = { name: string age: i32 uni: ?string }`
> - `rect = { A: i64 B: i64 C: i64 D: ?i64 }`

`StructDecl = ident "=" "{" {ident ":" ["?"] Type} "}".`

> b.)
> 
> ```
> Args = FixArgs ";" VarArgs .
> FixArgs = ident ":" Type { ";" ident ":" Type } .
> VarArgs = "..." ident .
> Type = "i32" | "string" .
> ```
> 
> *Beispielsatz*: 
> 
> - `x: i32; n:string; p:i32; ...others`

`Args = ident : Type ";" (VarArgs | { ident : Type ";" }).`

## Aufgabe 03 - Beseitigung von Linksrekursion

> Beseitigen Sie in folgender Grammatik die enthaltenen LL(1)-Konflikte. Geben Sie dazu eine umgeformte EBNF Grammatik ohne Rekursion an. Beseitigen Sie mögliche Linksrekursionen durch Umformung in eine Iteration (nicht durch Umformung in Rechtsrekursion).
> 
> ```
> Fields = Type Assigns .
> Assigns = ident "=" Expr .
> Expr = ident | number | Expr ( "==" | "!=" ) ( ident | number ) .
> Type = ident | Type "->" ident .
> ```
> 
> Beispielsätze:
> 
> - `int -> bool a = 5 == b`
> - `bool b = 0`
> - `int -> int -> int -> bool d = a == b != c`

```
Type = ident {"->" ident}.
Expr = (ident | number) {("==" | "!=") (ident | number)}.
```
